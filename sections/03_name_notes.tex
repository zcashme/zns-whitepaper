\section{Name Notes}
\label{sec:name-notes}

A Name Note is an Ironwood output whose memo records a name transition by encoding the type of name change, the name, the associated Unified Address when applicable, the expiration value, and a predecessor reference. Its \texttt{rseed} is derived from that transition, so the note commitment binds the transition the memo records.

\subsection{Memo encoding}

The Name Note memo is a 512-byte field. A parser removes its maximal trailing sequence of zero bytes. The remaining bytes MUST be UTF-8. The colon byte (\texttt{0x3a}) separates fields. The first field MUST be the exact ASCII bytes \texttt{ZNS}. Extra fields, missing fields, and empty required fields are rejected.

The name field MUST contain between 1 and 63 bytes, each of which is ASCII \texttt{a}--\texttt{z} or \texttt{0}--\texttt{9}.

The remaining bytes encode one transition in one of the following formats:

\begin{center}
\texttt{ZNS:claim:<name>:<ua>:<expires\_at>:<prev>}\\
\texttt{ZNS:update:<name>:<ua>:<expires\_at>:<prev>}\\
\texttt{ZNS:release:<name>:<ua>:none:<prev>}
\end{center}

The \texttt{<expires\_at>} field is either the canonical ASCII decimal encoding of a Unix timestamp in whole seconds or the exact ASCII bytes \texttt{none}. The value \texttt{none} indicates that the registration has no fixed expiration. A \texttt{release} MUST encode \texttt{none} as its \texttt{expires\_at} value and the Unified Address of the binding being released as its \texttt{ua} value.

The \texttt{prev} field is the 64-character lowercase hexadecimal encoding of the predecessor Name Note's \field{cmx}: the 32-byte canonical little-endian encoding of its extracted note commitment, as recorded in the on-chain action that created it. A \texttt{claim} has no predecessor and uses 64 zeroes.

A Name Note parser MUST reject a memo that does not match one of these encodings.

\subsection{Transition representation}

To derive the note's \texttt{rseed}, interpret the encoded transition as the tuple

$$\sigma = (\alpha, n, u, e, p)$$

where:
\begin{itemize}
  \item $\alpha$: The exact ASCII bytes \texttt{claim}, \texttt{update}, or \texttt{release}.
  \item $n$: The raw bytes of the name field.
  \item $u$: The raw bytes of the \texttt{ua} field.
  \item $e$: The raw bytes of the \texttt{expires\_at} field.
  \item $p$: The 32 raw bytes decoded from \texttt{prev}.
\end{itemize}

Define the fields $f$ of the transition as

$$f = \alpha \parallel \mathtt{0x3a} \parallel n \parallel \mathtt{0x3a} \parallel u \parallel \mathtt{0x3a} \parallel e.$$

These are the memo bytes that follow the leading \texttt{ZNS:} and precede the colon before \texttt{prev}.

\subsection{Commitment inputs}

A Name Note is a bound note: the sender does not sample its \texttt{rseed} at random but derives it from the transition.

Define the binding domain $D$ as the 16 ASCII bytes \texttt{ZNS\_\_\_Name\_Notes}, and the record kind $\kappa$ as the single byte \texttt{0x01}. Let $\ell$ be the byte length of $f$. Then

$$\mathsf{rseed}_\sigma = \mathsf{BLAKE2b{-}256}\big(D,\; \kappa \parallel \mathsf{I2LEOSP}_{64}(\ell) \parallel f \parallel p\big),$$

where $\mathsf{BLAKE2b{-}256}(D, x)$ is unkeyed BLAKE2b with a 32-byte output, the 16-byte personalization $D$, and input $x$. $\mathsf{I2LEOSP}_{64}(\ell)$ is the eight-byte unsigned little-endian encoding of $\ell$. The final $p$ is exactly 32 raw bytes and has no length prefix. The length prefix separates $f$ from $p$, so distinct transitions give distinct hash inputs.

Because $e$ is included in $f$, the \texttt{rseed} cryptographically binds the expiration value recorded in the Name Note. Because $p$ is included, it binds the predecessor.

The remaining commitment inputs follow from $\mathsf{rseed}_\sigma$ exactly as for any Ironwood note, whose note plaintext lead byte is \texttt{0x03} \cite{zip2005}. Let $\underline{\rho}$ be the 32-byte encoding of the note's $\rho$, which is the nullifier revealed by the same action. Let $\mathsf{g}\star_{\mathsf{d}}$ and $\mathsf{pk}\star_{\mathsf{d}}$ be the 32-byte encodings of the recipient's diversified base and transmission key, and $\mathsf{v}$ the note value. Then

$$\psi_\sigma = \mathsf{ToBase}\big(\mathsf{PRF^{expand}_{rseed_\sigma}}(\mathtt{0x09} \parallel \underline{\rho})\big),$$

$$\mathsf{pre\_rcm} = \mathtt{0x0B} \parallel \mathsf{g}\star_{\mathsf{d}} \parallel \mathsf{pk}\star_{\mathsf{d}} \parallel \mathsf{I2LEOSP}_{64}(\mathsf{v}) \parallel \underline{\rho} \parallel \mathsf{I2LEOSP}_{256}(\psi_\sigma),$$

$$\mathsf{rcm}_\sigma = \mathsf{ToScalar}\big(\mathsf{PRF^{expand}_{rseed_\sigma}}(\mathsf{pre\_rcm})\big).$$

$\mathsf{PRF^{expand}}$, $\mathsf{ToScalar}$, $\mathsf{ToBase}$, and the field types are those defined for Ironwood by the Zcash Protocol Specification and ZIP 2005 \cite{zcash-protocol,zip224,zip2005}. The value $\mathsf{rcm}_\sigma$ is the Pallas scalar-field element used as the Ironwood note-commitment randomness. The value $\psi_\sigma$ is the Pallas base-field element supplied to the Ironwood note commitment construction. The canonical encoding of either field element is its 32-byte little-endian field representation.

The note plaintext carries $\mathsf{rseed}_\sigma$ as usual. A Name Note is otherwise an ordinary Ironwood note: a receiver that follows ZIP 212 and ZIP 2005 decrypts it and recomputes its commitment without ZNS-specific rules \cite{zip212,zip2005}.

Changing the binding domain, the record kind, field order, the field separator, the length width, byte order, hash parameters, or the predecessor encoding changes the protocol version and requires new test vectors.

\subsection{Commitment verification}

A verifier derives $\mathsf{rseed}_\sigma$ from the encoded transition, derives $\psi_\sigma$ and $\mathsf{rcm}_\sigma$ from it, combines them with the remaining note components using the standard construction \cite{zcash-protocol,zip224}, and reconstructs the note commitment. The verifier needs the recipient address, the note value, and the action's nullifier and \field{cmx}. It needs no decryption key.

The Name Note passes commitment verification only if the reconstructed value equals the \field{cmx} recorded in the on-chain action.

This equality establishes only that the transition encoded in the memo is cryptographically bound to that output. It does not establish Mint authorization, user authorization, or the current registry state.
